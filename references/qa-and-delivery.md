# QA, Rehearsal & Delivery｜校验与可靠交付

## 双稿一致性检查

- 使用同一 `outline.json`，不要分别独立设计 Projection 和 Notes 的章节；
- 内部 `id` 唯一；两稿显示的自然章节 `title/order` 逐项一致，不显示 ID 或序号；`minutes` 合计与总时间一致；
- 原理公式、示例设定和数值不矛盾；
- 图示在对应节点出现，Notes 有操作指导；
- Notes 的转场指向投屏下一节点；
- 禁止 Speaker Notes 引入未在投屏或附录提到的关键数学符号或复杂新概念；
- 凡修改一个节点，检查上下两个节点的转场。

可用 `python scripts/check_alignment.py --outline outline.json --projection projection.md --notes speaker_notes.md` 做结构校验。脚本无法自动证明数学正确、渲染正确或讲述自然，这些仍需要人工审核。

## 彩排与时间

推荐至少进行：

- **无稿路径复述**：仅凭投屏纲要，用 3–5 分钟串全场，看是否存在逻辑断裂；
- **全程彩排**：真实语速，加互动、切页与演示时间；
- **突发缩时**：按 `must_keep` 保护核心链，其他节点预留 30 秒版；
- **追问模拟**：抽 5 个“为什么”、2 个“有什么反例”、2 个“实际工程怎样定位”；
- **媒介复核**：投屏分辨率、字号、公式字体、代码换行、网络、链接、权限、交互演示。 

## 飞书 / Google Docs / PPT 可移植输出

- 普通代码块一般只是源码，不应假定自动 Mermaid 渲染。确认目标环境的“文本绘图”组件是否支持；必要时导出 PNG 备用。
- HTML 预览与直接在文档正文执行交互脚本不同；交互演示预备本地文件和静态截图。
- Google Docs/飞书导入 Markdown 时，LaTeX 和 Mermaid 可能需要人工转换，不要假定公式保真。
- 所有附件/云端链接在交付前打开验证；文件名使用英文、版本号明确、主/辅文件角色明确。

## 下载失败处理

若沙箱附件无法下载，先确认本地文件存在、字节数与校验；若多个格式/ZIP 均失败，不再重复换名打包，改用用户已连接的 Google Drive、Notion、GitHub 私有仓库等实际可访问的云端渠道。上传后读取验证内容、确认权限，再给已返回的实际 URL。不要编造链接或宣称用户端一定能下载。

## 安全与版权发布门槛

公开前扫描：API key、账号、企业标识、内网 URL、客户和员工姓名、会议录音转录、私有架构图、未批准性能数据、未授权截图或教材原图。必要时用完全虚构的公开演示替代；无法明确获准就不发布。企业实战数据不应藏在 Skill 里作为“案例”。第三方图片和代码需要遵守许可。

## 发布验收

公开的版本应能在一个全新主题上成功生成一对对齐稿件，并通过自动校验。发布时提供 README、版本号、示例输入、期望输出、许可和已知限制。后续记录失败案例，优先修流程规则而不是堆新文案。
