# Technical QA｜概念、公式和老板追问备答

## 四层知识标准

对每一个主讲概念，按以下四层准备；不要求四层全部放投屏：

| 层级 | 必须准备的问题 | 典型失败 |
|---|---|---|
| L1 定义 | 能否一句话说清楚对象、输入与输出？ | 只说一堆同义词 |
| L2 例子 | 能否用固定场景演算一步？ | 例子与公式不一致 |
| L3 机制 | 关键式子成立的假设是什么？实现在哪一步？ | 记住形式但说不出依据 |
| L4 边界 | 有哪些反例、取舍、测量要求？ | 把理论可能性说成实测结论 |

## 概念辨析模板

- 共同点：为什么会混淆？
- 决定性区别：目标、数据、变量、尺度、条件有什么不同？
- 最小反例：哪种情况可以明显区分？
- 在真实系统中：错误理解会导致什么诊断失误？

## 技术真实性标签

在公开材料中区分四种表述：

- **定义/定理**：给出公式及前提。
- **示意例子**：显著标明假设数字，禁止冒充 benchmark。
- **推断/假说**：说明为什么推测，说明尚缺哪项证据。
- **实测结论**：至少有硬件/软件版本、输入、度量方法、对照及复现路径；不能凭记忆补指标。

公式类严谨性检查：记号索引一致（如 r_t/r_{t+1}）、离散/连续和时域条件说明、目标函数最小化还是最大化、概率分布是否归一、任何梯度停止传播的位置说明。

## 被打断时的回答格式

1. **复述问题**：“你是在问 X 依赖哪些前提，对吗？”
2. **给核心回答**：一句话明确核心机制或承认未知。
3. **给依据或反例**：选一个公式/最小操作，不强行扩展。
4. **回到进度**：“这与 P07 的结论相关；完整证明在附录，目前先回到 P08。”

不知道时可说：“这一点我现在只能确认理论关系，具体实现细节我没有在当前框架版本下验证。这里先标记待核对。”不捏造代码行为或实验数据。

## 课后复盘评分维度

优先收集可观察信号，而不是笼统的“讲得好”：是否有听众能复述闭环；问题集中在哪一节点；哪幅图减少了疑惑；哪些节点超时；是否发生术语解释或公式修正；讨论是否指向行动。区分讲者自我感受与外部反馈。
